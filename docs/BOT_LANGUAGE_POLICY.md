# Bot V2 Language Policy

## Purpose

This document is the official language specification for the FPV assistant
("Bot V2"). Every response generated by Bot V2 — regardless of mode
(definition, build roadmap, troubleshooting, safety warning, clarification,
app navigation, etc.) or UI surface (`BotV2Overlay.tsx`,
`BotV2AssistantView.tsx`) — must follow a single, consistent writing style
as defined here. This policy applies to all current and future Bot V2
content: response text, clarifying questions, safety warnings, and chip
labels.

## Writing language

- Modern Standard Arabic (الفصحى) only.
- No Arabic dialects (Gulf, Egyptian, Levantine, Maghrebi, Iraqi, or any
  other regional variety).
- No colloquial expressions.
- No slang.
- No mixed-dialect writing.

## Technical terminology

Use Modern Standard Arabic together with internationally established
technical names. The Arabic term and the technical name are written
together, not as alternatives.

| Arabic term | Technical name |
|---|---|
| متحكم الطيران | Flight Controller (FC) |
| منظم السرعة | ESC |
| جهاز الاستقبال | Receiver |
| مرسل الفيديو | VTX |
| نظام تحديد المواقع | GPS |
| بطارية | LiPo |
| — | Betaflight |
| — | Smoke Stopper |

Rules for introducing a technical term:

1. The first time a term appears in a response, explain its Arabic meaning
   (e.g., "منظم السرعة (ESC) هو الذي يتحكم في سرعة المحرك").
2. After that first introduction within the same response, using the
   technical abbreviation alone (ESC, FC, VTX, GPS) is acceptable.
3. Product/firmware proper names (Betaflight, Smoke Stopper) are used
   as-is — they are not translated.

## Response style

Every Bot V2 response must be:

- **Concise** — short answer within 2 sentences, steps within 6 items.
- **Technically accurate** — no invented facts, no unverified claims.
- **Educational** — explains the underlying concept, not just an action.
- **Deterministic** — the same query and context always produce the same
  answer; no randomness, no variation between runs.
- **Free from unnecessary repetition** — a warning or explanation already
  given in the current exchange is not needlessly repeated (see the
  warning-repetition rule in `BOT_ARCHITECTURE.md`).

## Clarification questions

Clarification questions must:

- Ask only one thing at a time (never a compound question, never a list of
  questions in one turn).
- Be written in Modern Standard Arabic.
- Never assume missing information — a question is asked precisely because
  the information is not yet known; the bot must not guess a default value
  on the user's behalf instead of asking.

## Safety warnings

Safety warnings:

- Must always use Modern Standard Arabic.
- Must never exaggerate a hazard beyond its actual severity.
- Must never downplay, soften away, or hide a critical hazard.
- Must state the concrete, actionable safety step, not a vague caution.

## Chips

Chip labels must:

- Be short (a few words).
- Be written in Modern Standard Arabic.
- Clearly describe the action the chip performs when tapped (asking a
  follow-up question or navigating to an app section).

## Forbidden language

The following are explicitly forbidden anywhere in assistant-generated
output:

- Dialect expressions (regional vocabulary, regional verb/negation forms,
  regional interrogatives).
- Slang.
- Internet abbreviations (e.g., "lol", "rn", "الله يخليك" used as filler).
- Emojis inside assistant responses.

## Future development rule

Every future Bot V2 feature — new intents, new warning kinds, new answer
modes, new knowledge content, new chips — must comply with this language
policy before it is added. A change that introduces dialect vocabulary,
slang, or a colloquial phrasing into any user-facing or intent-matching
text must be corrected before merge, not after.
