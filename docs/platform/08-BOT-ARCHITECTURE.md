# معمار البوت — العقل الموحّد للمنصة

> **حالة الوثيقة:** قرار معماري مثبَّت. التنفيذ الموسّع **لم يبدأ بعد** وبدؤه
> ممنوع قبل إغلاق الأركان الثلاثة (الدروس · البناء · البرامج). هذه الوثيقة هي
> ما يُبنى عليه حين يحين وقته، وهي أيضاً القيد الذي يمنع بناءه قبل أوانه.

---

## 1. القرار في جملة واحدة

البوت **ليس مصدر معرفة**. هو **طبقة فهمٍ وتوجيهٍ فوق مصادر المنصة الحقيقية**:
يفهم ما يريده المستخدم، ويجد المصدر الموثوق الموجود فعلاً داخل التطبيق،
ويفتحه له في مكانه الدقيق — أو يقول بوضوح إنه لا يعرف.

كل جملة يقولها البوت يجب أن يكون لها **أصل قابل للإشارة إليه**: مقال أو مصطلح
أو عقدة تشخيص أو حكم توافق على مشروع المستخدم أو صفحة إعداد. الجملة التي لا
أصل لها لا تُقال.

---

## 2. ما هو موجود اليوم — تدقيق صادق

للبوت اليوم نظامان منفصلان تماماً في المستوى:

**طبقة الفهم — موجودة وجيدة وتُحفَظ:**

| الملف | السطور | ما يفعله |
|---|---|---|
| `data/knowledge/botQueryAnalysis.ts` | 301 | تطبيع عربي · تهجئات · اختصارات |
| `data/knowledge/botV2/intentClassifier.ts` | 365 | ١٧ نيّة + استخراج كيانات + درجة ثقة |
| `data/knowledge/botV2/safety.ts` | 122 | تصنيف الخطورة قبل أي شيء آخر |
| `data/knowledge/botV2/sessionContext.ts` | 325 | مُخفِّض حالة الحوار عبر الأدوار |
| `data/knowledge/botV2/contextualWarning.ts` | 362 | تحذير مرتبط بالسياق + منع التكرار |
| `data/knowledge/botV2/modeSelector.ts` | 180 | اختيار شكل الإجابة |
| `data/knowledge/botV2/composer.ts` | 327 | تركيب الرد |
| `data/knowledge/botV2/engine.ts` | 113 | خط الأنابيب الكامل |

هذه الطبقة **تبقى**. إعادة كتابتها من الصفر ستكون خسارة صافية: تصنيف النية
والسلامة وسياق الحوار هي أصعب ما في البوت، وهي تعمل.

**طبقة المعرفة — هي المشكلة:**

| الملف | السطور | ما فيه |
|---|---|---|
| `data/knowledge/botV2/knowledgeBase.ts` | 386 | **١٤ عقدة معرفة مكتوبة يدوياً** |
| `data/knowledge/botConceptRegistry.ts` | 510 | ١٤ معرّف مفهوم خاص بالبوت |
| `data/lkb/aklIndex.generated.ts` | 850 | فهرس مولَّد يسدّ الفجوات |

**الحكم:** هذه قاعدة معرفة ثانية. أربع عشرة عقدة مقابل موسوعة فيها اثنتا عشرة
مقالة للـESC وحدها، و١١٩ مصطلحاً، و١٦ شجرة تشخيص، ومحرّك أحكام يعرف قطع
المستخدم. البوت اليوم يجيب من نسخة مصغَّرة فقيرة من محتوى المنصة، بينما
المحتوى الحقيقي يبعد عنه استدعاء دالة واحدة.

كل مقال جديد نكتبه يزيد الفجوة، لأن الموسوعة تكبر والبوت لا.

## 3. المبدأ: مصدر واحد، لا نسخة

```
                     ┌─────────────────────────────┐
                     │  طبقة الفهم (موجودة)        │
                     │  تطبيع · نية · كيانات ·     │
                     │  سلامة · سياق الحوار        │
                     └──────────────┬──────────────┘
                                    │
                     ┌──────────────▼──────────────┐
                     │  طبقة الاسترجاع (تُبنى)     │
                     │  عقد واحد فوق كل السجلات    │
                     └──────────────┬──────────────┘
                                    │
   ┌──────────┬──────────┬──────────┼──────────┬──────────┬──────────┐
   ▼          ▼          ▼          ▼          ▼          ▼          ▼
 registry  glossary   dx trees   project    software   lessons   checklists
 (مقالات)  (مصطلحات) (تشخيص)   (المشروع)  (البرامج)  (الدروس)  (الفحوص)
```

القاعدة الملزمة: **لا يملك البوت أي بيانات لا تملكها واجهة أخرى.** إن احتاج
البوت حقلاً غير موجود، يُضاف إلى السجل الأصلي فتستفيد منه الواجهة أيضاً — لا
يُضاف إلى ملف خاص بالبوت.

`knowledgeBase.ts` لا يُحذف عند التحويل: يُعاد توجيه عقده الأربع عشرة إلى
معرّفات حقيقية في السجلات، فتتحول من **محتوى** إلى **خرائط نيّة**، ولا يضيع
شيء مما كُتب فيها.

## 4. عقد الاسترجاع

واجهة واحدة، هي المدخل الوحيد إلى المعرفة:

```ts
interface BotQuery {
  raw: string;                 // كما كتبه المستخدم
  normalized: string;          // بعد التطبيع العربي
  intent: Intent;              // من طبقة الفهم
  entities: ExtractedEntities;
  level?: KbLevel;             // مستوى المستخدم إن عُرف
  route?: string;              // الصفحة التي هو فيها الآن
  project?: ProjectSnapshot;   // مشروعه، بإذنه
}

interface BotSource {
  kind: 'article' | 'glossary' | 'dx' | 'finding' | 'software' | 'lesson' | 'checklist';
  targetId: string;
  titleAr: string;
  route: string;               // من resolveLinkRoute حصراً
  relevance: number;           // درجة الصلة
  confidence: 'typed-spec' | 'derived' | 'manual-required';
  version?: string;            // إصدار البرنامج حين ينطبق
  lastReviewed?: string;
  warningsAr: string[];
}

function retrieve(q: BotQuery): BotSource[];   // مرتَّبة، ولا تعيد شيئاً غير موجود
```

**ما يجب أن يدعمه الاسترجاع:** البحث الدلالي · المصطلحات · الاختصارات ·
التهجئات العربية البديلة · الإنجليزية · الأخطاء الإملائية البسيطة · النية ·
سياق الصفحة · سياق المشروع · مستوى المستخدم · نوع الطلب · إصدار البرنامج.

**ما هو جاهز فعلاً:** التطبيع العربي (تشكيل · تطويل · ألف · أرقام عربية) ·
المسافة المعدَّلة للأخطاء الإملائية · ٧٨ مجموعة مرادفات — كلها في
`data/kb/search/`، مثبتة بـ`testKbSearch` (٦٩ تأكيداً). الاسترجاع يُبنى فوقها
لا بجوارها.

**ما ينقص ويجب بناؤه:** ترجيح بالنية · ترجيح بالمشروع · ترجيح بالمستوى ·
دمج نتائج من سجلات مختلفة في ترتيب واحد.

## 5. عقد البيانات الوصفية — التغذية التلقائية

الشرط: *«لا أريد تعديل البوت يدوياً كل مرة نضيف مقالاً.»*

يتحقق هذا فقط إن حمل كل عنصر معرفة بياناته الوصفية بنفسه. الموجود اليوم في
`KbArticle` يغطي أكثر مما يبدو:

| المطلوب | الحقل الموجود | الحالة |
|---|---|---|
| العنوان | `titleAr` · `titleEn` | ✅ |
| المرادفات · الكلمات المفتاحية | `keywordsAr` · `keywordsEn` | ✅ |
| الأنظمة المرتبطة | `moduleId` · `relatedArticleIds` | ✅ |
| البرامج المرتبطة | `links[kind='betaflight']` | ✅ |
| القطع المرتبطة | `MODULE_PART_SLOTS` | ✅ |
| المسارات | `KbPath.articleIds` | ✅ |
| مستوى المستخدم | `levels` | ✅ |
| الإصدار · تاريخ المراجعة | `sources[].version` · `lastReviewed` | ✅ |
| التحذيرات | `safetyLevel` + كتل `warning` | ✅ |
| الوجهة داخل التطبيق | `/kb/${moduleId}/${id}` | ✅ |
| **النوايا المدعومة** | — | ❌ يُضاف |
| **الأعراض** | جزئياً في أشجار التشخيص | ❌ يُوحَّد |
| **الإجراءات المتاحة** | — | ❌ يُضاف |

الحقول الثلاثة الناقصة تُضاف إلى `KbArticle` **اختيارية**، فلا تُبطل ٦٠+ مقالاً
مكتوباً، ويملؤها كل مقال جديد. الاختبار يفرض ملأها على ما يُكتب بعد اليوم لا
على ما كُتب قبله — وهذا فرقٌ بين معيارٍ يرتفع وبين كسرِ عملٍ قائم.

## 6. عقد الوجهات — لا رابط وهمي

كل وجهة يقترحها البوت **يجب** أن تمر عبر `resolveLinkRoute` في
`data/kb/registry.ts`. تعيد الدالة `null` لأي هدف غير موجود، فيصبح الرابط
الميت خطأ برمجياً لا خطأ تجربة.

الأنواع المدعومة اليوم: `article` · `lesson` · `betaflight` · `assembly` ·
`roadmap` · `dx` · `glossary` · `checklist` · `external`.

يُضاف للبوت: `project` (قطعة أو حكم داخل المشروع) · `software` (صفحة برنامج
خارج Betaflight) · `checklistItem`.

**ممنوع** أن يقول البوت «اذهب إلى قسم البرامج». يقول «افتح صفحة Ports» ويفتحها،
أو لا يقول شيئاً.

## 7. النوايا — ما يجب أن يميّزه البوت

الموجود اليوم ١٧ نيّة في `intentClassifier.ts`، مصنَّفة حول البناء والأعطال.
المطلوب إضافة الأنواع التي تفرضها المنصة الجديدة:

| النية | مثال | ما يفعله البوت |
|---|---|---|
| `explain` | «أريد شرح UART» | مقال + طبقة تناسب المستوى |
| `navigate` | «خذني إلى صفحة Ports» | يفتح الوجهة مباشرة |
| `diagnose` | «الريسيفر لا يتحرك» | يبدأ شجرة تشخيص من أأمن فحص |
| `project_check` | «ما المشكلة في مشروعي؟» | أحكام محرّك التوافق |
| `software_setup` | «أين أجد إعداد DShot؟» | صفحة الإعداد + أثره + تراجعه |
| `compare` | «ما الفرق بين AIO وStack؟» | مقارنة موثقة، لا رأي |
| `learn_next` | «أريد متابعة الدرس» | الدرس التالي حسب تقدمه |
| `add_part` | «هل هذه البطارية مناسبة؟» | حكم على قطعة في سياق مشروعه |
| `missing_data` | «ما البيانات الناقصة؟» | الأسئلة المفتوحة على مشروعه |
| `safety_warning` | أي طلب خطر | تحذير قبل الخطوة لا بعدها |

الفرق بين `explain` و`diagnose` ليس تجميلياً: الأول يفتح نصاً، والثاني يبدأ
إجراءً له ترتيب سلامة إلزامي.

## 8. سياق المستخدم — بإذنه

يقرأ البوت، عند الإذن: المستوى · المسار الحالي · الدروس المكتملة · المشروع ·
القطع · البرامج · إصدارات الـFirmware · الأسئلة المفتوحة · الأعطال المسجلة ·
نتائج الاختبارات · آخر صفحة زارها.

مثال ملزم — «كيف أوصل الـGPS؟» لا يُجاب عنه بنص عام. يحاول البوت أولاً معرفة:
نوع متحكم الطيران · نوع الـGPS · الجهد المطلوب · البروتوكول · منافذ UART
المتاحة · الـFirmware · وجود Compass · ثم **يعلن ما لا يعرفه**.

كل هذا يُقرأ من `readProjectSnapshot()` و`useKbProgress()` — مصادر موجودة، لا
مخزن جديد.

## 9. البوت لا يخترع — القاعدة غير القابلة للتفاوض

**ممنوع منعاً باتاً:** اختراع Pinout · اختراع UART · اختراع جهد · اختراع إعداد ·
اختراع توافق · اختراع مصدر · إعطاء قيمة عامة تصلح لكل المشاريع · ادّعاء معرفة
قطعة غير مسجلة · معلومة غير مرتبطة بإصدار · استنتاج بثقة عالية عند نقص البيانات.

عند نقص البيانات يقول صراحةً: «لا أستطيع تأكيد ذلك» · «أحتاج طراز اللوحة» ·
«أحتاج Pinout الرسمي» · «أحتاج إصدار الـFirmware» · «أحتاج عدد خلايا البطارية» ·
«هذا الحكم تقريبي» · «راجع دليل الشركة قبل التوصيل».

هذه ليست قاعدة جديدة على المنصة: محرّك الأحكام في `data/project/verdicts.ts`
يطبّقها فعلاً — قاعدة هامش التيار تُعلَن `unknown` مع تسمية البيانات الناقصة
لأن مصدرها الوحيد الموثوق هو جدول اختبار الدفع من الشركة. **البوت يرث هذا
السلوك لأنه يقرأ من المحرك نفسه، لا لأنه يقلّده.**

---

## 10. أشكال الإجابة — ثمانية، لا واحد طويل

`modeSelector.ts` يختار الشكل. المطلوب:

1. **إجابة سريعة** — تعريف أو توضيح قصير.
2. **شرح تعليمي** — متدرّج، بروابط دروس.
3. **تشخيص** — أسئلة متتابعة تقود داخل الشجرة، تبدأ بأأمن فحص.
4. **تحليل مشروع** — أحكام على قطع المستخدم ببياناته.
5. **تنقّل** — يفتح الوجهة.
6. **خطوات تنفيذ** — مرتبطة ببرنامج أو قطعة، بتحذيراتها.
7. **مقارنة** — على بيانات موثقة.
8. **متابعة تعلم** — الدرس التالي حسب التقدّم.

استخدام شكل واحد لكل الحالات هو بالضبط ما يجعل البوت يبدو ذكياً ويكون عديم
الفائدة.

## 11. حدود البوت

البوت يفتح محتوى التطبيق ويستخدم أدواته، **ولا يجعل الشاشات غير ضرورية**.
دوره: الفهم · التوجيه · البحث · التلخيص · التشخيص · تفسير النتائج · تشغيل
إجراءات آمنة · ربط الأقسام.

أما الجداول والمخططات والمشاريع والإعدادات الكاملة فتبقى في واجهاتها
المتخصصة. بوتٌ يحاول أن يكون التطبيق كله ينتهي إلى كونه نسخة أسوأ منه.

## 12. الأداء

الحزمة الأولية اليوم **2,310 kB** (−5.1% عن خط الأساس 2,435 kB). الموسوعة
كلها خلف تحميل كسول: `registry` في حزمة منفصلة (906 kB)، والمصطلحات (89 kB)،
وأشجار التشخيص (155 kB).

**قيد ملزم:** طبقة الاسترجاع لا تستورد السجلات استيراداً ثابتاً في حزمة
الإقلاع. تُحمَّل عند أول سؤال حقيقي، ويُبنى فهرس خفيف (معرّف · عنوان · كلمات
مفتاحية · نية · مستوى) منفصل عن المحتوى الكامل.

## 13. الاختبارات — بوابة القبول

لا يُعتبر البوت جاهزاً لأنه «يجيب». يجب أن تغطي الاختبارات:

فهم النية · اختيار المصدر الصحيح · عدم اختراع معلومات · طلب البيانات الناقصة ·
فتح الوجهة الصحيحة · ربط السؤال بمشروع المستخدم · التمييز بين التعليمي
والتشخيصي · العربية والإنجليزية · التهجئات · الاختصارات · الأخطاء الإملائية ·
سلامة الردود الحساسة · الاستشهاد بمصدر داخلي · اختلاف إصدارات البرامج · **عدم
فتح رابط غير موجود** · **عدم اقتراح خطوة خطرة قبل التحذير** · **عدم تشغيل
تشخيص المحركات قبل نزع المراوح**.

عبارات إلزامية في مجموعة الاختبار: «فلايت كنترولر» · «فلاش كنترول» · «FC» ·
«ESC» · «إكسبريس إل آر إس» · «ExpressLRS» · «Betaflight» · «بيتافلايت» ·
«Binding» · «بايند» · «البورت» · «UART» · «لا يظهر OSD» · «الدرون ينقلب» ·
«المحرك لا يدور» · «البطارية تهبط بسرعة».

ثم رحلة كاملة من طرف إلى طرف: يريد بناء درون ← يحدد الهدف والمستوى ← يفتح
مشروعاً ← يُرشَد إلى الدروس ← يُساعَد في القطع ← تُعرض التعارضات ← يُفتح مخطط
التوصيل ← يُنقَل إلى إعداد البرنامج ← يُساعَد في Binding ← يُرشَد إلى
الاختبارات ← يُشخَّص العطل ← تُسجَّل النتيجة في المشروع.

## 14. ترتيب التنفيذ — والسبب

```
المرحلة ١   ركن الدروس والمعرفة        ← نحن هنا
المرحلة ٢   ركن البناء والمشروع
المرحلة ٣   مركز البرامج والـFirmware
المرحلة ٤   تدقيق الترابط بين الأركان
المرحلة ٥   البوت
المرحلة ٦   رحلة كاملة عبر البوت
```

**لماذا البوت أخيراً، لا أولاً:** البوت طبقة فوق مصادر. بناؤه فوق مصادر ناقصة
ينتج شيئين، كلاهما ضرر: بوتاً يجيب من العموميات لأنه لا يجد مصدراً، أو بوتاً
بقاعدة معرفة خاصة تسدّ النقص — وهي بالضبط المشكلة القائمة اليوم مضاعفة.

كل مقال يُكتب في المرحلة ١، وكل مدقق في المرحلة ٢، وكل صفحة برنامج في المرحلة
٣، تصبح تلقائياً شيئاً يعرفه البوت في المرحلة ٥ — بشرط أن تُكتب وهي تحمل
بياناتها الوصفية. **هذا هو الشرط الذي يجعل المراحل الأربع الأولى عملاً على
البوت وإن لم يُلمَس ملف واحد من ملفاته.**

## 15. الالتزام

- لا قاعدة معرفة ثانية. مصدر واحد لكل حقيقة.
- لا رابط لا يفتح شيئاً.
- لا رقم لم يُوثَّق.
- لا خطوة خطرة قبل تحذيرها.
- لا ادّعاء اكتمال بلا اختبار يثبته.
- ولا بوت قبل أن يكون تحته ما يستحق أن يُقرأ منه.
