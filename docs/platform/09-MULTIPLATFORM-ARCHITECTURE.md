# معمار متعدد المنصات — قلب واحد يخدم الهاتف والويب

> **حالة الوثيقة:** قرار معماري مثبَّت وملزم لكل ما يُبنى بعد اليوم.
> **ما لا تعنيه:** بدء موقع ويب الآن. لا يُبنى موقع منفصل في هذه المرحلة.
> **ما تعنيه:** ألّا يُتخذ اليوم قرار يجعل الانتقال غداً هدماً وإعادة بناء.

---

## 1. القرار في جملة واحدة

تطبيق الهاتف **واجهة أولى** لا منتجاً وحيداً. المحتوى والمشروع ومحرك الأحكام
والبحث والتشخيص والقاموس ومركز البرامج والبوت تُبنى **قدرات مستقلة عن شكل
الواجهة**، تستهلكها واجهة الهاتف اليوم وواجهة الويب غداً بلا إعادة اختراع.

---

## 2. الطبقات — أين يعيش كل شيء

```
┌──────────────────────────────────────────────────────────────┐
│  واجهات العرض  (خاصة بكل منصة، ولا تُفرَض مشاركتها)          │
│  React Native/Capacitor — هاتف   │   واجهة ويب — لاحقاً       │
└────────────────────────┬─────────────────────────────────────┘
                         │  تستهلك فقط، ولا تحتوي منطقاً
┌────────────────────────▼─────────────────────────────────────┐
│  طبقة المنصة  src/platform/  — محايدة تماماً تجاه الواجهة     │
│  الوجهات · التخزين المُصدَّر · العقود المشتركة                 │
└────────────────────────┬─────────────────────────────────────┘
                         │
┌────────────────────────▼─────────────────────────────────────┐
│  المحركات والسجلات  src/data/  — بلا React وبلا راوتر         │
│  السجل · القاموس · أشجار التشخيص · محرك الأحكام · المشروع     │
│  · البحث · مركز البرامج · طبقة معرفة البوت                    │
└──────────────────────────────────────────────────────────────┘
```

**القاعدة الملزمة:** لا يستورد `src/data/**` من `src/components/**` ولا من
`src/hooks/**` ولا من `react` ولا من `react-router-dom`. اختبار يفرض ذلك.

| البحث | `data/kb/search/*` | ✅ |

## 4. المعرّفات والوجهات

هوية المحتوى **ليست مساراً**. المعرّف ثابت، والمسار اشتقاق منه.

```ts
type Destination =
  | { kind: 'article';  id: string }
  | { kind: 'module';   id: string }
  | { kind: 'glossary'; id: string }
  | { kind: 'dx';       id: string }
  | { kind: 'lesson';   id: string }
  | { kind: 'betaflight'; id: string }
  | { kind: 'roadmap';  id: string }
  | { kind: 'project' } | { kind: 'assembly' } | { kind: 'checklist' }
  | { kind: 'search';   query: string }
  | { kind: 'external'; url: string };

resolveDestination(d): string | null   // المحلل المركزي الوحيد
```

كل ما يقترح وجهة — البوت، البحث، الأحكام، المقالات، الإشعارات، الروابط
المشتركة — يُنتج `Destination` مجرَّدة، ثم تحوّلها كل منصة إلى شكل رابطها.
وجهة لا تُحلّ تعيد `null`، فيصير الرابط الميت **خطأ برمجياً لا خطأ تجربة**.

هذا ما يجعل هذه ممكنة لاحقاً بلا إعادة كتابة: رابط ويب مشترك · نتيجة بحث ·
إجابة بوت · إشعار · مشاركة مشروع · تحسين محركات البحث.

---

## 5. البيانات المحلية — نموذج واحد قابل للترحيل

كل ما يُخزَّن محلياً وله قيمة يجب أن:

1. يملك **نموذجاً مكتوباً** بالأنواع لا شكلاً ضمنياً.
2. يحمل **إصدار مخطط** صريحاً.
3. يمرّ بدالة **تحقق** ترفض الشكل الفاسد بدل الوثوق به.
4. يكون **قابلاً للتصدير** إلى نصّ مستقل عن المتصفح.
5. يكون **قابلاً للترحيل** من إصدار إلى إصدار.
6. **لا يخزّن كائنات كاملة** بل معرّفات تُعاد ترطيبها من السجل الحيّ.

النقطة السادسة هي التي تجعل المزامنة ممكنة أصلاً: رزمة معرّفات صغيرة تُرسَل
وتُستقبَل، والمحتوى يبقى في السجل. مشروع محفوظ بمعرّفات ينتقل بين هاتف ومتصفح
وخادم بلا تعارض؛ مشروع محفوظ بكائنات كاملة يحمل معه نسخة قديمة من الكتالوج.

**عقد المزامنة المستقبلي** (لا يُنفَّذ الآن، ويُصمَّم اليوم بحيث يمكن):
بيانات محلية · بيانات مشتركة · بيانات من الخادم · آخر تحديث · حلّ التعارض ·
العمل دون اتصال.

---

## 6. المحتوى مبني للعرض المتعدد أصلاً

هذا القرار **متَّخذ ومنفَّذ منذ البداية**: المقال ليس نصاً منسّقاً بل قائمة
كتل مصنّفة (`KbBlock`: فقرة · قائمة · خطوات · جدول · تحذير · تعريف · مفتاح-قيمة
· مقارنة · مخطط · أسئلة · قائمة فحص)، وست طبقات عرض (سريع · مبسّط · تقني ·
عملي · تشخيصي · مرجعي).

النتيجة: العارض لا يعرف موضوع المقال، والمقال لا يعرف حجم الشاشة. شاشة هاتف
تعرض الكتل عمودياً، ومتصفح حاسوب يستطيع عرض عمودين وجدولاً واسعاً وطباعة —
**من البيانات نفسها بلا تعديل محتوى**.

---

## 7. الأدوات: منطق منفصل عن الرسم

مدقق التوافق · خريطة الطاقة · مخطط التوصيل · توزيع UART · مقارنة القطع ·
تقارير المشروع · أشجار التشخيص · محلل الإعدادات — هذه كلها أقوى على شاشة
حاسوب.

القاعدة: تُبنى **الحسبة والبيانات** أولاً كدوال خالصة تعيد بنية معطيات، ثم
يأتي الرسم فوقها. اليوم عرض هاتف مبسّط؛ غداً عرض ويب واسع وتصدير وطباعة
ومشاركة رابط — **بلا لمس المنطق**.

`data/project/verdicts.ts` هو النموذج القائم: يعيد `Finding[]` تحمل الادّعاء
والتعليل والأدلة والثقة والبيانات الناقصة والإجراءات والوجهات. الشاشة ترسم؛
المحرك يحكم.

---

## 8. الصلاحيات والخصوصية

نموذج البيانات يجب أن يستطيع لاحقاً التمييز بين: خاص · مشترك عبر رابط · منشور
للعامة · للقراءة فقط · قابل للتعاون.

**قاعدة اليوم:** لا يُخزَّن أي شيء بطريقة تجعل نشره لاحقاً يتسرّب تلقائياً.
المشروع والملاحظات ومحادثات البوت وسجلات التشخيص **خاصة افتراضياً**، ولا
تُعرَض في رابط عام إلا بموافقة صريحة ولاحقة.

---

## 9. المجتمع داخل المنصة لا بجوارها

المجتمع سيعمل على الويب أيضاً، ويجب أن يرتبط بالمعرفة والمشاريع: مشاركة مشروع
أو تقرير · ربط منشور بدرس · ربط سؤال بشجرة تشخيص · الإشارة إلى قطعة.

**حدّ صارم:** محتوى المجتمع غير الموثق **لا يصير مصدراً تلقائياً** لإجابات
البوت ولا للدروس. الطريق من نقاش إلى مرجع يمرّ بمراجعة واعتماد بشري، وإلا صارت
الموسوعة انعكاساً لأكثر الآراء تكراراً لا لأدقّها.

---

## 10. ما يُشارَك وما لا يُشارَك

| يُشارَك بين المنصتين | قد يُنفَّذ لكل منصة على حدة |
|---|---|
| الأنواع ونماذج البيانات | مكوّنات العرض |
| مخططات التحقق | التخطيط والتنقل البصري |
| منطق الأعمال والمحركات | الإيماءات ولوحة المفاتيح |
| خدمات الاسترجاع | الرسوم والمخططات |
| قواعد السلامة | حالات التحميل والفراغ |
| النصوص والمحتوى | |
| دوال التنسيق الخالصة | |
| الاختبارات | |

**لا تُفرَض إعادة استخدام مرئي مصطنعة.** مكوّن واحد يخدم شاشة ٣٩٠ بكسل وشاشة
حاسوب معاً ينتهي إلى إضعاف الاثنتين.

## 11. الممنوعات المعمارية

- معرفة داخل JSX
- قواعد توافق داخل شاشة
- منطق تشخيص مرتبط براوتر
- روابط نصية متفرقة بلا محلل مركزي
- بيانات مشروع بلا إصدار ولا ترحيل
- اعتماد مباشر على `localStorage` من المكوّنات
- استيراد الموسوعة في حزمة الإقلاع
- نسخة ثانية من المحتوى للموقع
- منطق خاص بالويب داخل تطبيق الهاتف قبل الحاجة
- موقع مستقل يكرر المشروع القائم

## 12. الترتيب — ولماذا الويب أخيراً

```
١  إغلاق ركن الدروس والمعرفة        ← نحن هنا
٢  إغلاق ركن البناء والمشروع
٣  إغلاق مركز البرامج والـFirmware
٤  تدقيق الترابط بين الأركان
٥  البوت
٦  خطة إطلاق منصة الويب — مستقلة ومدروسة
```

منصة ويب فوق أركان ناقصة تضاعف النقص على واجهتين بدل واحدة. والانتظار ليس
تأجيلاً: كل ما يُبنى في المراحل الأربع الأولى وفق هذه الوثيقة **هو عمل على
منصة الويب** وإن لم يُكتب سطر واحد منها.
